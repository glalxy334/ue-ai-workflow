# UE＋AI 工作流

当前工作流版本：**3.5**。

用于 Unreal Engine 项目的首次接入、有库或无库工作流、定向调查、需求确认、任务记录、可选 AI 交接、实现与分层验收。

这是工作流 Skill 与审核角色配置示例，不是 UE 插件，不附带模型、子智能体运行时或安全沙箱。当前为待验证的发布候选，不保证所有客户端版本兼容。

## 工作方式

```text
L0 咨询／局部问题：定向核实 → 回答或按本轮明确授权处理
L1／L2：需求与边界 → 证据与方案 → 实现与交付
正常文档流程：确认需求与方案 → 授权创建唯一任务记录 → 用户选择当前 AI 或其他 AI
 → 实施者核对并列明范围 → 本轮实施授权 → 直接实现 → 自检与获准验证 → 用户验收
无文档保底：用户拒绝必要初始化后，以对话摘要承载，不写文档；实施仍须本轮授权
```

- 从需求相关系统入手，不默认扫描整个项目。
- 优先复用现有系统、接口和有效文档；没有合适框架时先讨论。
- 不展示完整代码、不设候选区、不逐版审批；实施者按已确认需求和本轮实施授权直接修改正式项目。
- 暂不调用审核子智能体；保留主智能体自检和获准验证，独立审核仅在用户单独明确要求时启用。
- 仅确认需求不等于立即执行；历史授权不自动延续。
- 每一行代码都有注释，新增或修改的代码注释使用中文，技术标识符保留原名；判断逻辑增加适当 Debug。
- 有库／无库、当前 AI 继续／其他 AI 接手和 C++ 实现偏好是独立维度，均不自动启用审核。
- 先询问尚未确定的知识库配置与 C++ 实现偏好，不凭缺少文档认定功能不存在。
- 正常流程一个任务一份记录；拒绝必要初始化时可使用无文档保底，但不绕过已有强制规则。
- 同一工程目录仅一个写入者，接手不自动继承修改授权。

本发行版同步自本地 v3.5。唯一的 Skill 内容适配是将个人维护知识库绝对路径改为 `{维护知识库根目录}`，使用时由用户配置；其他业务规则保持不变。本地安装目录不会因本次发布而被改写。

## 安装

安装前核对当前客户端官方文档。不要覆盖现有同名技能或角色；先备份、比较，再决定是否替换。

### Codex

1. 将完整 `skills/ue-ai-workflow` 目录复制到个人技能目录 `~/.agents/skills/ue-ai-workflow`。
2. 仅在用户要求独立审核时，才需要配置 `adapters/codex/ue-code-reviewer.toml`；默认个人模式不需要审核角色。
3. 新建会话，检查技能是否被发现；未发现时检查客户端支持及其实际配置目录，不把复制成功视为加载成功。同一技能不要在多个发现目录重复安装。

### ZCode

1. 将完整 `skills/ue-ai-workflow` 目录复制到 `~/.zcode/skills/ue-ai-workflow`，或通过客户端支持的技能导入方式加载。
2. 仅在用户要求独立审核时，才需要配置 `adapters/zcode/ue-code-reviewer.md`；默认个人模式不需要审核角色。
3. 在客户端检查技能是否已启用，然后新建会话。

两端复制的 Skill 不会自动同步；升级时核对版本或文件内容标识。

## 使用

需求确认：

> 使用 $ue-ai-workflow。先只读接入当前 UE 项目，核对知识库设置与已有项目规则，定向调查新增开宝箱功能；需求确认前不进入实现，不自动创建文档。

确认范围并实施：

> 使用 $ue-ai-workflow。按唯一任务记录或我提供的保底摘要核对已确认需求，列明准确修改范围，取得我的本轮实施授权后直接修改正式工程；完成后自检并汇报验证结果，不调用独立审核。

用户要求独立审核时：

> 使用 $ue-ai-workflow，身份：实现端。完成修改后按审核调用约定发起独立审核，只读审查本次改动。

调用技能、指定执行者和确认需求都不等于批准工程修改。需要项目路径或任务记录但无法唯一定位时，AI 应询问，不扫描整台电脑。

## 第一次使用前

先按 [验证说明](docs/VALIDATION.md) 做无工程写入的调用测试。确认技能加载、模式选择和只读调查行为，而不是只看主智能体声称“加载成功”。

需要修改项目规则时先取得批准；可参考 [可选项目规则](examples/project-rules.md)。保留项目已有文档名称和有效结构，不因使用本 Skill 全量迁移文档。

## 安全与已知限制

- Skill 是行为指导，不是文件锁、访问控制或权限沙箱。
- 独立审核不是默认步骤；主智能体自检不能替代用户要求的独立审核，也不能替代编译、Editor、PIE、存档重载或打包验证。
- 不允许两个 AI 同时写同一工程；角色记录不能阻止另一个进程写入。
- 蓝图、地图和其他二进制资产需要额外可审查证据；文本读取工具不能证明资产运行正确。
- 不上传真实工程、私有任务记录、账号配置、日志或密钥到本仓库。
