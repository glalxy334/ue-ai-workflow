# UE＋AI 工作流

用于 Unreal Engine 项目的需求澄清、定向系统调查、个人快速实现、可选团队交接与独立审核、验证和文档交付。

这是工作流 Skill 与审核角色配置示例，不是 UE 插件，不附带模型、子智能体运行时或安全沙箱。当前为待验证的发布候选，不保证所有客户端版本兼容。

## 工作方式

```text
个人模式（默认）：定向调查 → 需求澄清与确认 → 本轮授权 → 直接实现 → 自检与获准验证 → 文档交付
团队模式（可选）：S0 接入 → S1 定向调查 → S2 需求澄清与冻结
 → S3 交接与候选准备 → S4 独立审核与用户批准
 → S5 受控实现、验证与复审 → S6 文档同步与交接
```

- 从需求相关系统入手，不默认扫描整个项目。
- 优先复用现有系统、接口和有效文档；没有合适框架时先讨论。
- 个人模式：不展示完整代码、不设候选区、不逐版审批；实现角色按已确认提示词和本轮实施授权直接修改正式项目。
- 暂不调用审核子智能体；保留主智能体自检和获准验证，独立审核仅在用户单独明确要求时启用。
- 仅确认需求不等于立即执行；历史授权不自动延续。
- 每一行代码都有注释；判断逻辑增加适当 Debug。
- 团队模式保留角色交接、候选核对和独立审核流程；同一工程目录仅一个写入者。

## 安装

安装前核对当前客户端官方文档。不要覆盖现有同名技能或角色；先备份、比较，再决定是否替换。

### Codex

1. 将完整 `skills/ue-ai-workflow` 目录复制到个人技能目录 `~/.agents/skills/ue-ai-workflow`。
2. 仅在用户要求独立审核时，才需要配置 `adapters/codex/ue-code-reviewer.toml`；默认个人模式不需要审核角色。
3. 新建会话，检查技能是否被发现；未发现时检查客户端支持及其实际配置目录，不把复制成功视为加载成功。

### ZCode

1. 将完整 `skills/ue-ai-workflow` 目录复制到 `~/.zcode/skills/ue-ai-workflow`，或通过客户端支持的技能导入方式加载。
2. 仅在用户要求独立审核时，才需要配置 `adapters/zcode/ue-code-reviewer.md`；默认个人模式不需要审核角色。
3. 在客户端检查技能是否已启用，然后新建会话。

两端复制的 Skill 不会自动同步；升级时核对版本或文件内容标识。

## 使用

需求确认（需求端）：

> 使用 $ue-ai-workflow，身份：需求端。先只读接入当前 UE 项目，定向调查相关系统，分析新增开宝箱功能；需求确认前不进入实现。

确认并实施（实现端）：

> 使用 $ue-ai-workflow，身份：实现端。按我确认的需求摘要和本轮授权直接修改正式工程，完成后自检并汇报验证结果；不调用独立审核。

用户要求独立审核时：

> 使用 $ue-ai-workflow，身份：实现端。完成修改后按审核调用约定发起独立审核，只读审查本次改动。

调用技能、指定身份和确认需求都不等于批准工程修改。需要项目路径或任务记录但无法唯一定位时，AI 应询问，不扫描整台电脑。

## 第一次使用前

先按 [验证说明](docs/VALIDATION.md) 做无工程写入的调用测试。确认技能加载、模式选择和只读调查行为，而不是只看主智能体声称“加载成功”。

需要修改项目规则时先取得批准；可参考 [可选项目规则](examples/project-rules.md)。保留项目已有文档名称和有效结构，不因使用本 Skill 全量迁移文档。

## 安全与已知限制

- Skill 是行为指导，不是文件锁、访问控制或权限沙箱。
- 独立审核不是默认步骤；主智能体自检不能替代用户要求的独立审核，也不能替代编译、Editor、PIE、存档重载或打包验证。
- 不允许两个 AI 同时写同一工程；角色记录不能阻止另一个进程写入。
- 蓝图、地图和其他二进制资产需要额外可审查证据；文本读取工具不能证明资产运行正确。
- 不上传真实工程、私有任务记录、账号配置、日志或密钥到本仓库。
