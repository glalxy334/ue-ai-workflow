# 公共文档与旧项目接入

优先沿用已有有效文档和路径，不强制重命名或复制成新体系。项目事实只维护一份权威入口，任务记录引用系统文档，不复制整本说明。

| 文档职责（建议名称） | 内容 | 不放什么 |
|---|---|---|
| 长期规则 `AGENTS.md` | 行为边界、审核授权、编码与验证约定 | 任务进度和系统接口全集 |
| 项目概览 `PROJECT_OVERVIEW.md` | 项目定位、UE 版本、运动系统等技术栈、模块插件、系统文档入口 | 任务流水 |
| 项目状态 `PROJECT_STATUS.md` | 当前任务、阶段、写入负责人、阻塞、待决和近期验证摘要 | 所有历史任务和完整手册 |
| 系统文档 `Systems/*.md` | 已实现能力、状态、接口、生命周期、依赖和限制 | 每次任务全过程 |
| 任务记录 `Tasks/TASK-*.md` | 一个任务的需求、调查、决策、审核、授权、验证与交接 | 重复整份系统说明 |

一个任务一份记录，不按 S0–S6 创建七份文件。小任务删去不适用章节。任务索引、依赖总图只在维护确有需要时增加。

## 系统文档字段

记录职责与非职责、能力状态、核心接口与调用限制、生命周期／状态所有权／清理、直接依赖和被依赖、配置与资产入口、限制和已知问题、最近核对日期及证据。

状态区分已实现已验证、已实现待验证、部分实现、设计未实现、已废弃和未知；“已验证”必须说明版本、环境和验证范围。

## 文档缺口

| 类别 | 处理 |
|---|---|
| 文档缺失 | 定向查相关实现，不推断功能不存在 |
| 文档过期 | 标记差异，核实受影响事实 |
| 功能缺失 | 有相关调查证据后讨论复用、扩展或新建 |
| 状态未知 | 有限补查；影响关键决策仍无法核实时暂停并询问 |

只有缺口影响本任务需求、复用、依赖、安全、验收或交接时才提出补文档；无关缺口只记录。文档缺失本身不是自动阻塞理由。

先基于证据准备草稿，将未知标为待确认；创建／更新路径和范围纳入授权，可合并批准。不未经批准修改公共文档，也不自行改项目规则来适配 Skill。

## 证据和交接

分别说明源码／蓝图／资产反映的实现、编译／Editor／PIE／打包反映的特定验证结果、公共文档的总结、历史记录的当时决策。证据冲突时调查原因，不机械规定一种来源永远优先。

交接记录包括任务与阶段、负责人、需求／候选版本、基线、已有改动归属、审核与批准范围、验证和未决项、下一步。原负责人完成获准记录并停止写入后，接收方核对并确认接手。
