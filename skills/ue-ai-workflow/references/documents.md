# 公共文档与旧项目接入

## 版本

对应工作流版本：3.5

## 项目规则与设置

知识库模式只决定检索、存放和沉淀方式，不改变需求确认、写入授权、编码、自检、验证或审核限制。AgentA／AgentB 执行者与 C++ 实现偏好均为独立设置。

先读项目实际 `AGENTS.md` 或项目已指定的规则文件；文件名以项目约定为准，不另建大小写或同义副本。文件不存在或未说明知识库配置时，先询问用户是否有本项目使用的知识库，再决定设置存放位置；不能仅凭文件缺失或配置缺失推断无库。

### 无库项目规则

1. 已有且一致的规则沿用，不重复追加。先说明缺失项、拟追加内容及文件位置，经明确授权后只追加，不修改、删除、重排原有内容。
2. 项目没有规则文件时，先一并询问是否允许创建 `AGENTS.md` 并加入所列规则；用户允许后才进入依赖初始化的后续流程，不把询问本身当作授权。
3. 缺少规则不等于有权写入；已有规则与拟加规则冲突时列出差异并等待用户裁定，不通过追加一条相反规则隐性覆盖。
4. 用户全部拒绝必要初始化时，适用 [无文档保底机制](workflow.md#无文档保底机制)。若已有规则强制留档等约束，先报告冲突，不能自行跳过。

### 有库项目设置

1. 读取知识库适用的约束与项目入口，只查相关模块，不遍历整个知识库。
2. 已有对应项目模块时在其中按规则创建或补充项目设置、任务入口；不直接在项目中创建规则副本，不为接入 Skill 搬动原有项目文档。
3. 没有对应项目模块时，说明拟创建的模块或登记项、位置、必要文档与任务记录位置，取得明确授权后创建；沿用已有项目登记方式，不强制新建文件夹。
4. 知识库设置不能覆盖项目原有约束。模块不唯一、配置与现状冲突、路径不可访问或权限不足时报告并等待，不自行创建替代库、覆盖或降级。

### 项目设置内容与变更

项目设置至少记录知识库模式与已确认位置、任务文档目录、实现偏好；仅补缺失项，不把模板占位符写成事实。首次询问尚未确定的实现偏好：

- **C++ 为主**：主要逻辑在 C++，编辑器以资源与参数配置为主；仅保留已说明理由并获确认的少量更合适的蓝图逻辑。
- **纯 C++**：逻辑、组件创建与初始化等按已确认方案在 C++ 实现，不使用蓝图编写业务逻辑；只保留必要资源与编辑器配置。

经相应文档写入授权保存设置；后续按当前明确有效的设置执行，不重复询问未变内容，不把偏好等同于实施授权。保底不保存项目设置，只在当前对话沿用，不承诺跨会话记忆。

用户明确要求改变偏好时，先确认适用范围，再追加变更日期、旧设置、新设置、明确替代关系及用户确认依据。保留旧文字，不以“最新条款优先”覆盖所有规则；不能借偏好变更放宽权限，也不自动改变已确认任务方案。知识库的记录格式与追加方式仍须符合其自身约束，冲突时先问用户。

## 文档职责

优先沿用已有有效文档和路径，不强制重命名或复制成新体系。

| 文档 | 内容 | 不放什么 |
|---|---|---|
| `AGENTS.md` | 原有项目约束；无库时经授权追加项目设置与工作流规则。 | 任务流水；未经授权的改写或隐性覆盖。 |
| `PROJECT_OVERVIEW.md` | 项目定位、UE 版本、技术栈、模块插件和系统文档入口。 | 任务流水。 |
| `PROJECT_STATUS.md` | 项目当前状态与近期验证摘要，具体字段遵循项目规则。 | 所有历史任务和完整手册。 |
| `Systems/*.md` | 能力、状态、接口、生命周期、依赖和限制。 | 每次任务全过程。 |
| 专属任务文档 | 已确认需求、调查依据、实施方案、范围、进度、验证与恢复入口；有库按项目模块约束，无库按下述优先级存放。 | 第二份任务主记录；未经验证的成功结论。 |

## 任务记录位置与生命周期

无库位置优先级：用户本轮指定位置，其次项目规则已配置的任务目录，否则使用项目内 `Docs/AI任务/`。有库使用知识库约束确定的对应项目位置，不在项目另存主记录。无法访问或写入时报告问题，不自行换路径或切入保底。

正常文档流程中，正式任务在需求与方案确认后、开始实施前，经明确的文档写入授权创建一份专属任务文档；原 AI 继续和其他 AI 接手共用同一主记录。创建记录不授权业务代码、资产或配置修改。咨询不强制建档；简单局部任务按风险裁剪，需要跨会话交接时仍保留足以恢复的唯一记录。

任务文档采用 [统一模板](templates.md#统一专属任务文档)，覆盖任务标识、已确认需求、调查结论及证据、完整实施方案、写入与验证范围、结果及恢复交接。实施方案必须允许说明新增／扩展功能、复用／配置／扩展／新建系统、新增／修改代码、资产与编辑器设置，不只是代码修改列表。

按已授权文档范围在以下节点更新，不机械要求每个动作都写流水：

- 实现及相应自测通过后，补充实际改动、检查证据和未验证项；需要用户配置时进入待编辑器配置／待功能验收，不提前关闭任务。
- 完成配置并按已约定验收清单测试、用户明确反馈通过后，补充最终结果并关闭任务。用户反馈与 AI 实测必须分别标明。
- 自测失败、部分通过、阻塞或暂停时，也更新已完成项、失败现象与原因；未知原因标待查，不编造根因。记录证据、未完成项和恢复入口。
- 用户明确暂停／取消时如实标记，不当作成功。正常恢复沿用原文档，核对必要当前事实并重新取得本轮实施授权。

保底流程取消后续所有文档创建与更新，仅在对话中交付上述内容，不因已有记录存在而继续回写。

## 需求调查证据

需求阶段可以读取与本任务相关的文档、源码、配置、日志和必要资产入口。

记录证据来源、读取范围、核对日期、当前状态和影响结论。区分：

- 项目文档表达的设计或历史决策；
- 源码、蓝图、配置和资产反映的实际实现；
- 编译、Editor、PIE、打包和资产加载反映的特定验证；
- 用户明确确认的产品需求；
- 推测、待查证和未验证项。

文档、源码和验证结果不互相替代。正式任务按所选知识库模式维护唯一记录，不以是否交 AgentB 决定是否建档；保底以用户传递的对话摘要恢复。实现时读取必要目标代码和影响方案的当前事实，不重复筛查整个系统或重读整套文档。任务记录不能替代当前工程事实。

## 系统文档字段

记录职责与非职责、能力状态、核心接口与调用限制、生命周期、状态所有权、清理、直接依赖、被依赖、配置与资产入口、限制、已知问题、最近核对日期和证据。

状态区分已实现已验证、已实现待验证、部分实现、设计未实现、已废弃和未知。

## 文档缺口

| 类别 | 处理 |
|---|---|
| 文档缺失 | 定向查相关实现，不推断功能不存在。 |
| 文档过期 | 标记差异，核实受影响事实。 |
| 功能缺失 | 基于调查证据讨论复用、扩展或局部新建。 |
| 状态未知 | 有限补查；影响关键决策且无法核实时暂停并询问。 |

只补与本任务需求、复用、依赖、安全、验收或交接有关的文档缺口。

公共文档创建或更新必须单独纳入本轮授权，不未经批准修改项目规则或公共文档。

## 任务交接

交接必须包含任务与阶段、负责人、需求版本、实施提示词版本、基线、相关文件内容标识、已有改动归属、授权范围、审核状态、验证、未决项和下一步。

正常流程向用户提供唯一任务文档准确路径，接手方确认实际可读；不可读时先报告，不假设共享权限。保底在对话输出足够完整的交接摘要，由用户传递，不要求新建文件。两者都保留用户选择原 AI 或其他 AI 的环节，不假设自动调度、共享记忆或文件锁。

项目实现事实仍按已有文档归属与本轮授权维护；知识摄取仅在有库且获准时进行，无库不自动建库，保底不写文档。不得把具体任务事实写回通用 Skill。
