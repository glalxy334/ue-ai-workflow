# 审核与实现后自检

## 版本

对应工作流版本：3.5

## 所有模式：实现后自检

有库、无库、保底及不同执行者均执行主智能体自检；不默认调用独立审核，不生成完整代码候选，不建立候选区或逐版审批。执行者由用户选择，接续任务不扩大授权。

正式写入前只核对：

- 本轮是否有明确写入授权；
- 初始化、任务文档、业务实施和验证的授权范围是否区分，保底是否保持不写文档；
- 目标文件、系统和功能是否仍在授权范围；
- 关键目标代码和已有改动是否发生影响方案的变化；
- 是否需要暂停询问用户。

正式写入后，主智能体执行以下自检，并如实报告结果：

| 检查维度 | 自检内容 |
|---|---|
| 需求覆盖 | 是否实现用户确认的目标，是否擅自增加功能。 |
| 系统与职责 | 修改位置是否属于主责系统，是否引入不必要的跨系统耦合。 |
| 复用与接口 | 是否遵循已查证接口、状态所有权、生命周期和复用结论。 |
| 正确性 | 成功、失败、取消、中断、重复触发、资源释放和事件清理。 |
| UE 风险 | 按需检查 UObject、Actor、Component 生命周期，C++／蓝图边界、输入锁、死亡清理、存档、异步加载和资产引用。 |
| 编码要求 | 每行新增或修改代码是否有中文注释，判断代码是否增加可关闭 debug，是否避免敏感日志，并满足适用项目规则；格式不支持注释时是否先说明并询问。 |
| 实现偏好 | 是否遵守项目已确认的 C++ 为主或纯 C++ 分工；新增蓝图逻辑是否超出原方案；资源、资产及新增功能是否有需求依据。 |
| 范围与安全 | 是否改动未授权文件、依赖、权限配置或他人改动。 |
| 验证 | 验证是否覆盖主要风险，证据是否对应实际变更。 |

自检不是独立审核，不得表述为“审核通过”。没有执行的编译、Editor、PIE、资产或打包验证必须标记为未验证。

## 可选独立审核

以下规则仅在用户单独明确要求独立审核时使用；有库、交接或高风险分级不自动触发。现有项目规则若要求不同流程，先列出冲突请用户裁定，不能自行追加相反规则覆盖。

### 审核材料

优先提供实际变更与差异、已确认需求、必要源码、相关基线、准确范围及验证证据。审核材料只读取获准对象，不为审核建立候选工程，不要求先向用户展示完整代码。

蓝图、地图和资产不能仅凭文字操作说明视为已经配置或验证；材料不可访问时说明缺口，不推定通过。

允许修改对象是主要授权边界；禁止改动清单是额外下限，不是白名单。审核授权不等于实施授权。

### 条件授权

所有模式区分需求确认、文档写入、业务实施和验证范围；可在用户一次明确答复中授权清楚列出的多个对象，但不能从文档初始化或选择执行者推定代码授权。正常流程仅按文档授权记录，保底只在对话说明。

未明确授权的操作不得从“按流程执行”、实现偏好或历史授权中推定。

### 独立审核

独立审核只有在用户单独明确要求后调用。审核者使用独立只读上下文，直接检查实际变更、必要源码、基线、范围和验证计划，不能修改或修复。没有实际能力时说明限制，不伪造独立审核；用户明确设置审核前提时不能擅自取消，应报告并等待决定。

审核结论只返回：

- 通过；
- 需修改；
- 阻止或待证据。

审核通过不代表编译、运行或用户验收通过。

### 正式写入前后

正式写入前核对需求、已确认实施方案、相关基线、单写入者和本轮准确授权。

发现影响方案的基线漂移时暂停并重新确认；不影响方案的局部变化可定向补查，正常流程按授权记录，保底只在对话报告。

正式写入后检查实际差异、已有改动保护和验证结果。实际变更偏离已确认需求、实施方案或授权范围时，停止相关动作并重新确认；偏离本身不自动触发独立复审，仍须用户单独明确要求。

回滚属于写入操作，必须单独授权，不能重置整个工程。

## 版本化验证状态

分别记录以下状态，不互相替代：

| 状态 | 含义 |
|---|---|
| 源码检查 | 已读取或已检查实际源文件和差异。 |
| 已修改 | 已写入目标文件，但不代表编译成功。 |
| 已编译 | 已完成相关编译或链接。 |
| Editor | 已在 UE Editor 中完成配置或检查。 |
| PIE | 已在 PIE 或等价运行场景验证。 |
| 资产 | 已确认蓝图、地图、材质、动画或其他资产实际状态。 |
| 打包 | 已完成目标打包或发布验证。 |

## 用户配置与完成条件

实现完成、源码检查通过或构建通过都不等于整个任务完成。按项目实现偏好，在实现及相应自测通过后交付必要资源、编辑器和少量已确认蓝图逻辑的详细配置步骤，以及需求阶段约定的验收清单；已执行测试失败时先处理，不宣称通过。

- 待编辑器配置：步骤已提供，但用户尚未明确配置完成。
- 待功能验收：用户明确配置完成，或任务无需额外配置，尚未反馈验收清单全部通过。
- 验证失败／部分通过／阻塞／暂停：说明已完成项、实际证据、未完成项与恢复入口，不标成功；正常流程按授权更新原记录，保底只在对话报告。
- 已完成：用户明确反馈按约定清单测试全部通过后，补充最终结果并关闭。模糊“好了”、步骤已交付、没有报错等均不替代明确反馈。

用户验收记为“用户反馈验收通过”，仅 AI 实际操作并观察到结果才记“AI 实测通过”。用户反馈不扩大到未执行或未覆盖的构建、Editor、PIE、资产、打包检查。普通任务不强制逐项截图；含糊、异常或关键风险时只索取必要证据。
