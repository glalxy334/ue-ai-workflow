# 审核调用约定

## 发起时机

在 S3 候选已准备且可冻结时自动进入 S4；在 S5 实施与获准验证完成后自动发起实际变更复审。纯需求咨询或没有候选时不为了完成流程而创建审核任务。

用户调用本工作流即表达按此流程请求独立审核；这不授权工程写入、额外付费服务或敏感信息外发。实际工具权限仍须核对。

## 平台能力检查

- Codex：核对角色是否已加载，以及实际创建工具是否支持角色选择。角色配置本身不强制只读；若父会话可写且子角色无独立工具限制，暂停合规审核，请求在真正只读环境进行，不更改全局沙箱或伪造权限。
- ZCode：核对 `ue-code-reviewer` 已加载、启用，且工具白名单仅为 Read／Grep／Glob。不要为方便读取资产而自动增加 Bash、Write、Edit 或 MCP。
- 若工具接口不同，使用本轮实际暴露的参数。没有角色选择参数时，不假装角色已被调用；提出适配或独立只读审核环境方案。
- 未验证角色加载、模型调用、只读限制的任一项，都明确标注，不把“文件已安装”写成“审核已可用”。

## 输入包

传递任务 ID、当前阶段、冻结需求与验收、代码基线及相关未提交差异、候选路径和内容标识、允许范围、必要系统入口、项目规则、已有验证及未验证项。

要求审核者直接检查实际候选，不只看实现摘要。不要提前提供主智能体的“已通过”判断引导审核。

## 内置审核派发提示词

由实现负责人填入真实材料后发送给已核实的独立只读审核角色，不要求用户复制。候选审核和实际变更复审共用此模板。提供子智能体可访问的位置；不能访问时传递获准的必要内容，不假设自动继承主对话。

```markdown
使用 $ue-ai-workflow，身份：独立审核者。只读完成本次审核，不实施、不修复、不另派审核者。

- Skill 与审核规则的可访问位置或内容：【填写】
- 审核类型：【候选审核／实际变更复审】
- 任务 ID、需求版本、已确认需求与验收标准：【填写】
- 项目约定、必要系统文档及源码／资产入口：【填写】
- 代码基线、相关已有改动及归属：【填写】
- 冻结候选位置、内容标识、修改范围和禁止操作：【填写】
- 验证与回滚计划、已有证据与未验证项：【填写】
- 复审附加材料：【用户批准记录、实际差异及与候选的一致性证据；首审标记不适用】

直接检查实际候选／变更和必要上下文，不只看实现摘要，也不继承主智能体的“已通过”判断。
按审核规则检查需求符合性、耦合、职责边界、复用、复杂度、异常清理、项目编码要求、权限范围与验证。
仅按需求相关性追加 UE 专项。材料缺失或不可访问时列出缺口，不推定通过。
不修改文件、不执行会产生写入的验证、不联网外发项目内容、不改变权限。
返回“通过／需修改／阻止或待证据”，并列出审核对象、问题位置、依据、影响、必须修复项、风险和未验证项。
结论通过也不代表用户批准正式工程修改。
```

## 等待与结果

记录实际子任务标识或平台可用的等效记录。等待结果完成，不只发出调用就宣布通过。等待期间可做无关只读整理，不改变候选和相关基线，不应用工程变更。

失败、超时、缺证据或角色不可用时报告阻塞；不要无上限重试。候选实质修订后重新冻结并审核。

保留审核者原结论，向用户提供摘要及证据位置。不能删除不利发现来获得批准。审核通过后请求用户批准准确候选及范围；复审发现偏差也不能自行修复。

## 无工程写入的验收

新会话中先让主智能体调用专用审核角色，审查一个纯文本候选并返回结论。检查真实子任务标识、实际工具权限、输入版本及结果；不要用尝试修改真实文件的方法测试只读性。

该测试仅验证角色调用、指令和权限可见性，不代表 UE 编译、PIE 或资产审核通过。
