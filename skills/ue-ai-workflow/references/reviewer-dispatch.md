# 审核调用约定

## 版本

对应工作流版本：2.6

本文件仅适用于团队模式、用户明确要求独立审核，或项目规则明确要求独立审核的场景。个人模式使用 [审核与实现后自检](review.md) 的自检清单，不读取本文件。

## 发起条件

独立审核仅在以下任一条件满足时发起：

1. 用户明确要求独立审核；
2. 本轮实施授权明确包含独立审核；
3. 用户确认某类任务必须经过独立审核。

调用 Skill 本身不代表请求独立审核。

需求调查、普通自检和没有实际候选时，不为了完成流程而创建审核任务。

## 能力检查

发起前核对：

- 审核角色是否实际加载；
- 是否能创建独立上下文；
- 是否能限制为只读工具；
- 是否能访问实际候选和必要源码；
- 是否能记录真实任务标识和返回结果。

角色配置存在不等于审核能力可用。无法确认独立性或只读权限时，必须说明限制。

如果本轮授权把审核设为正式写入前提，则审核不可用时暂停正式写入；如果本轮明确允许主智能体自检替代审核，才可以按该授权继续，但不得把自检称作独立审核。

## 输入包

传递：

- 任务 ID、当前阶段和工作流版本；
- 需求版本、已确认需求和验收标准；
- 项目规则、必要系统文档和源码入口；
- 代码基线及已有未提交改动归属；
- 实际文本候选或可访问候选位置；
- 修改范围、禁止操作和授权范围；
- 验证、回滚、已有证据和未验证项。

要求审核者直接检查实际候选，不只看实现摘要，也不提供主智能体的预先通过判断。

## 内置审核派发提示词

由实现负责人填写真实材料后发送给已核实的独立只读审核角色。

```markdown
使用 $ue-ai-workflow，身份：独立审核者。只读完成本次审核，不实施、不修复、不另派审核者。

- 工作流版本：【填写】
- 审核类型：【文本候选审核／实际变更复审】
- 任务 ID、需求版本、已确认需求与验收标准：【填写】
- 项目约定、必要系统文档及源码入口：【填写】
- 代码基线、已有改动及归属：【填写】
- 实际候选内容或访问位置：【填写】
- 修改范围、禁止操作和本轮授权：【填写】
- 验证、回滚、已有证据和未验证项：【填写】
- 实际变更复审材料：【用户批准记录、实际差异及与候选的一致性证据；首审填写不适用】

直接检查实际候选或实际变更和必要上下文，不只看实现摘要，也不继承主智能体的通过判断。
按审核规则检查需求符合性、调查依据、耦合、职责边界、复用、复杂度、正确性、异常清理、编码要求、权限范围和验证。
仅按需求相关性追加 UE 专项检查。
材料缺失或不可访问时列出缺口，不推定通过。
不修改文件、不执行会产生写入的验证、不联网外发项目内容、不改变权限。
返回“通过／需修改／阻止或待证据”，并列出审核对象、问题位置、依据、影响、必须修复项、风险和未验证项。
```

## 等待与结果

记录真实审核任务标识或平台等效记录，等待结果完成后再决定是否继续正式写入。

审核失败、超时、缺证据或角色不可用时，按本轮授权处理，不无限重试。

保留审核原结论。候选实质修订后重新冻结受影响内容并审核。

审核通过后，若本轮已授权，才能修改正式工程；若未授权，只向用户报告审核摘要并请求正式写入授权。

## 实际变更复审

默认由主智能体完成实际差异与候选的一致性自检。

只有用户明确要求、本轮授权明确包含，或实际变更偏离候选、需求和范围时，才发起独立实际变更复审。
