# 多工具协作与能力适配

## 版本

对应工作流版本：3.5

## 基本原则

通用流程不绑定平台 API。Codex、ZCode 和审核者的具体对应关系由用户决定，不能假设跨工具共享记忆、权限或文件锁。

需求调查不因缺少子智能体而阻塞。所有知识库模式与执行者共用同一授权、范围、编码、自检和验收限制；执行者接续不自动启用候选、逐版审批或独立审核。用户全部拒绝必要初始化时适用无文档保底，不因缺少文档强制停止获准实施。

## 能力核对

| 能力 | 核对要求 | 降级处理 |
|---|---|---|
| 项目读取 | 确认实际路径和允许读取范围。 | 只询问缺少的入口，不全盘搜索。 |
| 独立审核 | 仅用户单独明确要求后，确认独立上下文与只读能力。 | 说明限制，不伪造审核；用户明确设为实施前提时先报告并等待决定。 |
| 工程写入 | 确认实际写入权限、准确范围和本轮授权。 | 无授权时保持只读，不因接手任务准备候选工程或先行写入。 |
| UE 工具 | 确认能读取或修改蓝图、编译、运行 Editor、PIE 或打包。 | 未执行的操作标记为未验证。 |
| 外部检索 | 确认联网和外发范围。 | 项目事实优先从本地证据查证。 |

不在 Skill 中内置未经验证的跨平台调用命令。

## 执行者接续

需求调查与实现由当前会话连续推进，不模拟角色切换；用户选择交由其他 AI 接手时，按唯一记录或保底摘要接续。

先定向调查文档、源码、配置和必要资产，再提出会影响方案、范围、风险、验收或用户取舍的问题。小任务使用自然语言；功能范围、系统影响和后续依赖在需要时集中使用影响表。

正常流程中，正式需求与方案确认后、实施前，经文档写入授权建立唯一任务记录。有库按知识库项目模块约束，无库优先用户指定、其次项目配置、否则 `Docs/AI任务/`，不另建第二份主记录。创建后必须询问由 AgentA 全程完成还是 AgentB 接手，并输出准确任务路径，不自行选择。

AgentB 按用户提供的路径读取记录，确认实际可读，不假设同步、共享权限或自动调度。保底不写文档，改由用户传递对话内的需求、方案、证据和进度摘要；同样保留用户选择执行者的环节，不假设接手者能读取原会话。

实施者核对记录或保底摘要与已确认需求、必要当前事实，只读相关目标入口，不重复整轮调查。报告一致性与准确实施范围后，用户一次明确确认可同时确认一致性并授权所列业务写入。初始化或文档授权不授权代码实施；AgentA 与 AgentB 门槛一致。差异、缺项、记录不唯一或路径不可读时先报告，不自行重建、降级或改写需求。

正常流程在实现及相应自测后、失败／阻塞／暂停时，按授权更新同一记录；配置交付后标待配置／验收，用户明确反馈约定测试通过后才更新最终结果并关闭。保底全部改为对话报告，不回写已有文档。仅有库且获准时摄取主题知识；单次框架先标待验证，实现框架或修改 Skill 须另获授权。

获得本轮明确实施授权后，直接修改正式工程，保护已有改动；不要求先展示完整代码、建立候选区或逐版审批。

独立审核只在用户单独明确要求时调用，不因有库、交接或 L2 自动触发。项目原规则存在不同要求时先报告冲突并等待裁定，不自行改规则。审核能力不可用时如实说明，不伪造通过，也不擅自取消用户明确设置的前提。

所有路径执行主智能体自检与获准验证，按实现偏好交付必要配置及验收清单，源码完成不等于配置完成或最终验收通过。

## 独立审核者

仅在用户单独明确要求独立审核后执行。

使用独立只读上下文直接查看实际变更、必要源码、需求、基线、范围和证据，不要求先建候选区。

只返回通过、需修改或阻止／待证据，列出问题位置、依据、影响、必须修复项、剩余风险和未验证项。

不修改、不修复、不批准正式写入、不另派审核者。

## 单写入者与基线漂移

同一工程目录的代码、蓝图、资产、配置、公共文档和任务记录遵循单写入者。

写入前核对相关文件的版本标识与已有改动，正常流程仅按获准记录范围留痕，保底只在对话报告。发现外部改动时只补查受影响部分；影响需求、系统选择、实施范围或验收时暂停并重新确认。

多文件修改按同一已确认实施方案执行。中途失败时报告已完成和未完成对象，不自动部分回滚；回滚必须单独授权。

## Skill 副本维护

当同一 Skill 存在多个副本时，必须指定唯一编辑源，并记录复制方向和同步时间。

只从编辑源向目标副本同步；发现目标副本存在独立修改时停止覆盖并报告冲突。

同步完成后核对文件清单、版本标识和内容摘要；普通 UE 任务不要求填写 Skill 副本同步字段。

Skill 的版本以 `SKILL.md` 为权威，reference 文件只保留与其一致的版本标识，`agents/openai.yaml` 需同步校验内容。

## 跨会话或跨工具交接

交接材料沿用唯一任务记录或保底对话摘要，包含任务、当前进度、用户选定执行者、写入负责人、工作流版本、基线、需求版本、已确认方案、授权范围、审核状态、验证计划和下一步；仅在用户请求独立审核时记录审核材料，不新增第二份任务主记录。

执行者变化不自动转移写入权。原执行者停止写入后，接收方核对基线和未提交改动，再按本轮授权接手。

## 不默认启用的能力

不自动创建分支、工作树、候选工程、安装依赖、修改权限、联网外发项目内容或跨工具调度。

不默认启用候选工程或独立审核，执行者交接由用户选择。与其他 UE Skill 配合时，本 Skill 负责总流程，专项 Skill 负责具体调查、实现、蓝图、资产或获准审核方法；专项能力不改变统一授权限制。
