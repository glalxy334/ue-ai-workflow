# 多工具协作与能力适配

## 版本

对应工作流版本：2.5

## 基本原则

通用流程不绑定平台 API。Codex、ZCode 和审核者的具体对应关系由用户决定，不能假设跨工具共享记忆、权限或文件锁。

需求调查不因缺少子智能体而阻塞。独立审核和工程修改必须满足本轮实际能力与授权。个人模式不因缺少交接角色而阻塞。

## 能力核对

| 能力 | 核对要求 | 降级处理 |
|---|---|---|
| 项目读取 | 确认实际路径和允许读取范围。 | 只询问缺少的入口，不全盘搜索。 |
| 独立审核 | 确认能创建独立上下文并使用只读工具。 | 若审核是授权前提则暂停正式写入。 |
| 工程写入 | 确认实际写入权限、修改范围和本轮授权。 | 个人模式无授权时只给简短变更摘要；团队模式可准备获准的候选。 |
| UE 工具 | 确认能读取或修改蓝图、编译、运行 Editor、PIE 或打包。 | 未执行的操作标记为未验证。 |
| 外部检索 | 确认联网和外发范围。 | 项目事实优先从本地证据查证。 |

不在 Skill 中内置未经验证的跨平台调用命令。

## 个人模式负责人

个人模式下，需求负责人和实现负责人由同一会话承担，不模拟角色切换。

先定向调查文档、源码、配置和必要资产，再提出会影响方案、范围、风险、验收或用户取舍的问题。小任务使用自然语言；功能范围、系统影响和后续依赖在需要时集中使用影响表。

实施前输出简短变更摘要。用户明确回复“确认并实施”或等价指令后，摘要同时作为本轮需求确认和写入授权；单独“确认”不自动授权，除非项目规则或本轮已约定。

## 团队模式需求负责人

团队模式下，从项目规则、概览、状态、任务记录和主系统入手，定向调查文档、源码、配置和必要资产。

调查与询问交替进行，按需使用功能影响表、已确认规则表、待确认边界表和完整汇总。只有需要跨角色或跨工具交接时，才生成实施提示词。

## 团队模式实现负责人

读取交接提示词、本轮授权和必要目标代码，核对提示词与当前事实是否仍一致，不重新筛查整个系统或重读整套文档。

只有团队模式或用户明确要求候选时，才在对话文本中生成完整可核对候选。候选必须标明文件路径、基线、修改位置、变更内容、禁止操作和验证计划。

按本轮授权送独立审核。审核不是默认强制动作；但若本轮授权把审核设为正式写入前提，审核不可用时不得正式写入。

审核通过后，核对基线和授权范围，修改正式工程，保护已有改动，执行获准验证，并检查实际差异与候选一致。个人模式直接按变更摘要和本轮授权执行，并在写入后完成主智能体自检。

## 独立审核者

仅在用户明确要求或本轮授权明确包含审核时执行。

使用独立只读上下文直接查看实际文本候选、必要源码、需求、基线、范围和证据。

只返回通过、需修改或阻止／待证据，列出问题位置、依据、影响、必须修复项、剩余风险和未验证项。

不修改、不修复、不批准正式写入、不另派审核者。

## 单写入者与基线漂移

同一工程目录的代码、蓝图、资产、配置、公共文档和任务记录遵循单写入者。

写入前记录相关文件的内容快照或版本标识。发现外部改动时，只补查受影响部分；如果影响需求、系统选择、候选范围或验收，暂停并重新确认。

多文件修改按一个候选执行。中途失败时报告已完成和未完成对象，不自动部分回滚；回滚必须单独授权。

## Skill 副本维护

当同一 Skill 存在多个副本时，必须指定唯一编辑源，并记录复制方向和同步时间。

只从编辑源向目标副本同步；发现目标副本存在独立修改时停止覆盖并报告冲突。

同步完成后核对文件清单、版本标识和内容摘要；普通 UE 任务不要求填写 Skill 副本同步字段。

Skill 的版本以 `SKILL.md` 为权威，reference 文件只保留与其一致的版本标识，`agents/openai.yaml` 需同步校验内容。

## 角色交接（仅团队／跨工具）

交接记录必须包含任务、阶段、角色、写入负责人、工作流版本、基线、需求版本、提示词版本、授权范围、审核状态、验证计划和下一步。

角色变化不自动转移写入权。原负责人停止写入后，接收方核对基线和未提交改动，再按本轮授权接手。

## 不默认启用的能力

不自动创建分支、工作树、候选工程、安装依赖、修改权限、联网外发项目内容或跨工具调度。

个人模式不默认启用角色交接、候选工程或独立审核。与其他 UE Skill 配合时，本 Skill 负责总流程，专项 Skill 负责具体调查、实现、蓝图、资产或审核方法。
