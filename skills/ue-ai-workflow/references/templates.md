# 共用模板

按需裁剪；记录必须反映真实状态，不把空字段或示例当作事实。写入这些记录也需要权限。

## 单任务记录

```markdown
# TASK-ID：任务名称

## 状态与责任
- 当前阶段、阻塞和下一步：
- 本轮角色、需求负责人、实现负责人、当前写入负责人：
- 项目路径、UE 版本、工作流版本／标识：
- 代码基线、已有未提交改动及归属：

## 需求与调查
- 需求版本、用户确认记录：
- 目标、非目标、验收标准：
- 主系统、实现证据、复用结论及直接依赖：
- 文档缺口和待确认事项：

| 需求／场景 | 当前能力与证据 | 缺口 | 处理方式 | 待确认 | 验收 |
|---|---|---|---|---|---|

## 候选与审核
- 候选目录准备授权、路径和允许操作：
- 候选标识／内容校验、需求版本及对应基线：
- 修改对象、禁止操作：
- 验证与回滚计划：
- 独立审核者、审核结论及证据：
- 必须修复项、剩余风险：
- 用户批准的候选标识、范围、操作、时间及确认记录：

## 实现、验证和交接
- 实际变更、复审结果：
- 实际执行验证、环境和证据：
- 未验证项与剩余风险：
- 文档更新范围、授权和结果：
- 原负责人停止写入、接收方核对及接手确认：
- 未决事项和下一步：
```

## 跨工具交接提示词

```markdown
使用 $ue-ai-workflow，身份：【填写接收方的需求负责人／实现负责人／独立审核者】。读取以下任务记录并执行对应内置指令；调用 Skill 不代表获得修改授权。

- 项目和任务记录位置：
- 当前阶段、你的角色、当前写入负责人：
- 工作流版本、UE 版本、代码基线和已有改动归属：
- 已冻结需求版本、目标、非目标、关键场景及验收：
- 主系统、可复用接口、相关证据及直接依赖：
- 未知项、文档缺口、当前阻塞：
- 允许操作及有效范围、候选准备目录、禁止操作：
- 当前候选标识、审核状态和用户批准范围：
- 验证与回滚计划：
- 下一步：

先核对上述记录和关键事实。差异影响需求、系统、范围或验收时暂停报告。
需求负责人按内置指令调查和持续澄清；实现负责人准备候选后主动使用内置派发提示词送审，不写正式工程。
独立审核者仅只读审核并返回结论，不修改、不另派审核者。
无须先向用户展示完整代码；没有独立审核通过或用户批准，实施者不得应用候选。
实现负责人获批后仅实施对应版本并执行获准验证，主动发起复审并记录未验证项。
```

## 用户可读审核摘要

```markdown
## 审核结论：通过／需修改／阻止或待证据
- 审核者、任务、需求版本、代码基线、候选内容标识：
- 需求覆盖、耦合与职责、复用及正确性结论：
- 拟修改对象和主要行为变化：
- 必须修复项、依据和影响：
- 剩余风险：
- 已有证据、待执行验证和回滚计划：
- 请求批准的准确范围与操作（仅审核通过后）：
```
