# 任务记录与交接模板

## 版本

对应工作流版本：2.6

模板按任务需要裁剪，不把空字段写成事实。

## 个人模式：简短任务笔记

复杂任务或中断任务可追加以下内容；简单任务不强制创建文件。

```markdown
# 任务：名称

- 状态：调查中／待确认／已授权实施／已修改／已验证／阻塞
- 目标与范围：本次要完成什么，明确不做什么
- 涉及系统与功能：主责系统、协作系统、现有能力和后续用途
- 变更摘要：拟修改或已修改的文件、资产和行为
- 关键证据：文档、源码、配置、日志、Git 状态或差异
- 验证状态：源码／编译／Editor／PIE／资产／打包
- 未验证项与下一步：风险、阻塞和后续动作
```

恢复中断任务时，优先核对 Git 状态、差异、未跟踪文件和目标文件内容；任务笔记用于补充决策和验证上下文，不替代当前工程事实。

## 个人模式：功能影响表

涉及多个系统、功能范围或后续依赖时，在决策节点或最终交付中使用：

| 子功能 | 主责系统 | 协作／依赖系统 | 现有能力与证据 | 本次处理 | 后续用途与确定性 |
|---|---|---|---|---|---|

## 个人模式：方案对比表

只有用户同意进行方案比较时使用：

| 方案 | 做法 | 优点 | 缺点 | 成本／风险 | 建议 |
|---|---|---|---|---|---|

## 团队模式：单任务记录

团队模式或复杂跨工具任务可以使用以下完整结构：

```markdown
# TASK-ID：任务名称

## 状态与责任
- 当前阶段、阻塞和下一步：
- 项目路径、UE 版本、工作流版本：
- 代码基线、相关文件标识、已有未提交改动及归属：
- 当前写入负责人和本轮授权：

## 需求与调查
- 需求版本、用户确认记录：
- 目标、非目标、验收标准：
- 主系统、实现证据、复用结论及直接依赖：
- 文档、源码、配置和资产调查边界：
- 禁止改动清单、文档缺口和待确认事项：

| 需求或场景 | 当前能力与证据 | 缺口 | 处理方式 | 待确认 | 验收 |
|---|---|---|---|---|---|

## 实施提示词与候选
- 提示词版本和交接位置：
- 候选内容、基线和应用清单：
- 允许修改对象和禁止操作：
- 验证、回滚和未验证项：

## 审核、实现与交付
- 审核是否启用、审核者和结论：
- 实际变更及与候选的一致性：
- 漂移复核、已有改动保护和多文件写入结果：
- 源码、编译、Editor、PIE、资产和打包证据：
- 未验证项、剩余风险、文档更新和下一步：
```

## 团队模式：跨工具交接

```markdown
使用 $ue-ai-workflow，身份：【需求负责人／实现负责人／独立审核者】。
读取以下任务记录并执行对应内置指令；调用 Skill 不代表获得修改授权。

- 项目和任务记录位置：
- 当前阶段、角色、写入负责人和工作流版本：
- 需求版本、目标、非目标、验收和关键异常：
- 主系统、可复用接口、相关证据及直接依赖：
- 代码基线、已有改动及归属：
- 实施提示词或候选位置：
- 允许操作、有效范围、禁止操作和本轮授权：
- 审核状态、验证计划、未决项和下一步：

先核对任务记录、关键事实、基线和授权。
差异影响需求、系统、范围、基线或验收时暂停报告。
实现负责人只读取必要目标代码；审核者仅只读审核，不修改、不修复、不另派审核者。
正式写入前核对授权；写入后记录实际差异和验证结果。
```
