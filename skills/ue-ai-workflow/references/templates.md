# 任务记录与交接模板

## 版本

对应工作流版本：3.5

模板按任务需要裁剪，不把空字段写成事实。

## 项目设置与追加变更

无库时仅在明确授权后向现有项目规则末尾追加缺失项；无文件时先取得创建文件及加入规则的许可。有库按知识库约束写入对应项目模块，不在项目中建规则副本。字段已经明确且一致时沿用，不重复写；以下占位内容不构成配置或授权。

### 首次设置字段

- 项目标识与实际入口：
- 知识库模式：有库／无库〔用户确认依据〕
- 知识库及项目模块位置：〔仅有库且已确认时填写〕
- 任务文档目录：〔用户指定／项目已有／无库默认 `Docs/AI任务/`〕
- 实现偏好：C++ 为主，资源配置为主并允许必要少量蓝图逻辑／纯 C++，仅必要配置
- 统一边界：需求确认不等于实施授权；不重复整轮调查；不设候选区或逐版审批；独立审核须用户单独明确要求；每行新增／修改代码有中文注释，判断增加可关闭 debug，格式不支持注释先询问；自检及验证要求同所有路径
- 用户设置确认及文档写入授权依据：

### 偏好变更字段

- 变更日期与用户确认依据：
- 旧设置及可定位原记录：
- 新设置与适用项目／范围：
- 明确替代关系：〔仅替代哪项旧偏好，不修改旧文，不覆盖其他约束〕
- 对已确认任务的影响及另行决定：〔不默认追溯改变方案〕
- 追加写入的明确授权与目标位置：

## 统一专属任务文档

正常流程中正式任务在需求与方案确认后、实施前经文档写入授权创建；AgentA 或 AgentB 使用同一份主记录。有库按对应项目模块约束存放，无库优先用户指定、其次项目配置、否则项目内 `Docs/AI任务/`。不重复创建项目副本与知识库副本。普通咨询不建档，简单局部任务按风险裁剪；保底仅在对话承载，不落地本模板。

### 一、任务标识与状态

- 任务 ID／标题、项目路径、适用 UE／插件版本：
- 工作流版本、需求版本、记录创建与更新时间：
- 知识库模式、项目设置入口、当前实现偏好：
- 唯一任务文档路径：〔向用户输出准确可复制路径〕
- 状态：已确认待选择执行者／一致性核对中／待实施授权／实施中／实现完成／待编辑器配置／待功能验收／验证失败／部分通过／阻塞／暂停／取消／已完成
- 用户选定执行者：AgentA 继续／AgentB 接手〔未决定前不得自行选择〕

### 二、已确认需求

- 用户确认依据与日期、需求版本：
- 目标、使用场景、行为、范围及非目标：
- 子功能与对应验收标准：
- 已确定事项与仍待确认项：〔不把建议写成已确认需求〕

### 三、调查结论与依据

- 相关系统、主责与协作关系：
- 现有能力、可复用入口和直接依赖：
- 已查证的源码／接口／资产／配置／日志位置、核对日期：
- 已查证事实、推断、版本适用边界及证据缺口：

### 四、实施方案

- 新增、扩展、调整或保留的功能及其对应需求：
- 各项采用复用／配置／扩展／新建的方式与理由：
- 新增系统、模块、文件、类、函数或接口：
- 修改的现有系统、代码与受影响调用：
- 新增或调整的资产、数据、资源、编辑器配置与必要文档：
- C++ 与少量必要蓝图逻辑的职责、选择理由及用户配置工作量：〔纯 C++ 不安排蓝图业务逻辑〕
- 执行顺序、依赖、必要调用与数据流：
- 异常处理、兼容影响、风险及各项验证方式：

不要求预先输出完整代码或完整蓝图节点教程，但必须足以说明做什么、新增或复用什么、在哪里做、如何衔接、如何验收。新增原确认范围之外的功能或蓝图分工，先向用户报告。

### 五、写入、核对与验证范围

- 初始化／任务文档写入授权及准确对象：
- 拟新增或修改的代码、资产、配置及禁止改动范围：
- 一致性核对者、需求版本与必要当前事实检查范围：
- 核对结果：一致／差异／信息不足／记录不唯一；差异及影响：
- 用户决定、业务实施授权的原文或可定位依据、时间与范围：
- 本轮获准的构建、Editor、运行等验证操作：
- 验收清单：逐项列场景、操作、预期结果、必要异常情况与通过条件

文档授权、设置偏好、历史授权和选择执行者不授权业务实施。核对一致后，用户一次明确确认可同时确认一致性并授权准确实施范围；接手或恢复时不自动延续旧授权。

### 六、实际结果与验收

- 实际新增／修改对象、行为、使用技术与版本：
- 自检项目、结果与证据：
- 已交付配置步骤及必要蓝图节点说明的位置：
- 验证明细：源码／编译／Editor／PIE／资产／打包；逐项填写通过／失败／部分通过／未执行及证据
- 用户配置反馈、验收清单结果与反馈依据：
- 验证来源：用户反馈／AI 实际操作并观察；两者分开记录
- 未验证项、踩坑、原因与处理：〔未知原因写待查〕
- 最终完成依据：〔用户明确反馈约定清单全部通过；仅配置完成不满足〕
- 知识摄取位置、适用条件与待验证结论：〔仅有库且获授权时填写，不作为任务完成前提〕

### 七、恢复与交接

- 已完成项、未完成项、当前失败／阻塞／暂停原因与证据：
- 当前源码、配置、资产或 Git 状态及已有改动归属：
- 下一步、恢复入口与接手必须核对的事实：
- 尚缺的用户决定、访问能力或本轮实施授权：
- 交接方式及接收方实际可读性：〔不假设共享记忆或自动调度〕

实现及相应自测后、最终用户验收通过后，按授权更新结果；自测失败、阻塞、部分通过或暂停时也更新恢复信息，不标成功。恢复沿用原记录，只核对必要当前事实，不重复整轮调查。

## 无文档保底交接摘要

仅用户全部拒绝必要初始化且不冲突于现有规则时使用。以下字段只在对话中提供，由用户传递给接手者，不创建或更新任何文档：

- 项目入口、需求版本、用户确认依据与当前实现偏好：
- 目标、非目标、验收标准及已确认方案：
- 相关系统、新增／修改对象、必要证据与风险：
- 已完成项、失败或阻塞、实际验证及未验证项：
- 用户选定执行者、当前状态、下一步和授权缺口：

接手者核对摘要与必要目标代码后请求本轮准确实施授权。缺少关键需求时先询问，不假装读取到原会话；拒绝文档不代表获得代码授权。

## 执行者跨工具接续

```markdown
使用 $ue-ai-workflow，接续用户已选择交由 AgentB 执行的任务。
读取以下唯一任务记录或保底对话摘要；调用 Skill 不代表获得修改授权。

- 项目和任务记录位置：
- 当前进度、用户选定执行者、写入负责人和工作流版本：
- 需求版本、目标、非目标、验收和关键异常：
- 主系统、可复用接口、相关证据及直接依赖：
- 代码基线、已有改动及归属：
- 统一任务文档或保底对话摘要、已确认实施方案：
- 允许操作、有效范围、禁止操作和本轮授权：
- 审核状态、验证计划、未决项和下一步：

先核对任务记录、关键事实、基线和授权。
差异影响需求、系统、范围、基线或验收时暂停报告。
只读取必要目标代码，不重新筛查系统或重读整套文档；独立审核仅在用户单独明确要求后按审核约定另行发起。
正式写入前核对本轮授权，不设候选区或逐版审批；写入后按已授权文档路径记录结果，保底只在对话报告。
详细配置交付不等于任务完成，用户明确反馈约定验收通过后才关闭。
```
