# 可选项目规则示例

本文件仅供参考，不是自动加载的 `AGENTS.md`。先与项目现有规则比较，取得负责人批准后再合并适用条款，不整份覆盖。

## 通用协作条款

- 明确需求负责人、实现负责人、独立审核者及当前写入负责人。
- 先调查需求相关系统，再与用户确认产品规则、系统选择和验收标准。
- 无需先向用户展示完整代码；实际候选由独立只读审核者检查。
- 独立审核通过后向用户提交摘要、候选标识、范围、风险、验证和回滚计划；用户批准后才修改工程。
- 候选准备目录和正式工程分别授权；单写入者规则也适用于共享文档。
- 保留已有有效文档，按任务补充相关缺口；创建或更新文档需要授权。
- 未验证项明确标记，不以源码存在代替运行验证。

## 项目自行决定的编码要求

这些偏好不属于通用 Skill 的强制要求。项目负责人按需要决定：

| 项目选项 | 决策要点 |
|---|---|
| 注释粒度 | 选择逐行、按逻辑块或只解释设计原因，并限定适用文件与改动范围 |
| 分支诊断日志 | 明确哪些判断需要日志、日志等级、频率及可关闭方式 |
| 命名与格式 | 优先采用项目现有规范和格式化配置 |
| 验证要求 | 根据改动风险规定编译、PIE、回归或打包，不机械要求每次执行全部检查 |

例如，若项目确实要求逐行注释、判断分支增加 Debug，应明确记录为该项目约定，并避免记录敏感信息、每帧刷屏或扩大到重写全部历史代码。
